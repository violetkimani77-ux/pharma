# ADR 0007 — Runtime and tooling baseline

- Status: Accepted
- Date: 2026-09-13
- Scope: application runtime and developer tooling

## Decision

HeriPHARMAS starts as a Node.js/Next.js/TypeScript application using the Next.js App Router and PostgreSQL through Prisma ORM.

The initial pinned baseline is:

- Node.js 24.21.x LTS line
- Next.js 16.3.3
- React 19.3.0
- TypeScript 5.9.2
- Prisma ORM 7.10.0
- PostgreSQL driver adapter `@prisma/adapter-pg`
- npm as the package manager

Prisma uses the ESM-first `prisma-client` generator with an explicit generated-client output directory. Database access uses the PostgreSQL driver adapter rather than the legacy Prisma client initialization model.

ESLint uses the current flat-config integration supplied by `eslint-config-next`.

## Why

- Next.js 16 is the current Active LTS line, and 16.3.3 includes the August 2026 critical security fixes.
- Prisma 7 requires modern Node/TypeScript and changes client generation and PostgreSQL connection setup; adopting the current supported model avoids starting on a deprecated persistence integration.
- Exact dependency versions are intentionally pinned. Dependency updates will be reviewed and tested rather than introduced through floating ranges.
- The runtime baseline is deliberately small. Authentication, authorization, observability providers, queues, and other infrastructure will be selected through separate ADRs after requirements and threat models are established.

## Important implementation rule

This ADR does **not** authorize overwriting an existing application manifest. The repository was inspected first and the `foundation` line contained no package manifest or lockfile. Therefore creating the initial manifest is initialization, not an upgrade.

A committed lockfile must be generated by the selected package manager in a real development/CI environment and reviewed before the runtime foundation is considered reproducible.

## Consequences

- ESM conventions apply throughout the TypeScript codebase.
- Prisma generated code is build output and is not committed.
- CI must run dependency installation from the lockfile, Prisma generation, type checking, linting, and production build.
- Runtime dependencies should remain minimal until the corresponding domain/security decision is documented.
